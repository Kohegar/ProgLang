## Задание 1

Возьмём числа `13/32` и `5/11`.

### 13/32

`32 = 2^5`, поэтому:

`13 = 8 + 4 + 1`

Значит:

`13/32 = 0.01101₂`.

### 5/11

Умножаем дробь на 2 и каждый раз записываем целую часть:

`5/11 × 2 = 0 + 10/11` → `0`  
`10/11 × 2 = 1 + 9/11` → `1`  
`9/11 × 2 = 1 + 7/11` → `1`  
`7/11 × 2 = 1 + 3/11` → `1`  
`3/11 × 2 = 0 + 6/11` → `0`  
`6/11 × 2 = 1 + 1/11` → `1`  
`1/11 × 2 = 0 + 2/11` → `0`  
`2/11 × 2 = 0 + 4/11` → `0`  
`4/11 × 2 = 0 + 8/11` → `0`  
`8/11 × 2 = 1 + 5/11` → `1`

Снова получили `5/11`, значит начинается повтор.

**Ответ:** `5/11 = 0.(0111010001)₂`.

## Задание 2

Возьмём `113.7`.

Целая часть:

`113 = 64 + 32 + 16 + 1`

`113 = 1110001₂`.

Для `0.7`:

`0.7 × 2 = 1.4` → `1`  
`0.4 × 2 = 0.8` → `0`  
`0.8 × 2 = 1.6` → `1`  
`0.6 × 2 = 1.2` → `1`  
дальше последовательность повторяется.

Поэтому:

`113.7 = 1110001.1011001100...₂`

Нормализуем:

`1.1100011011001100...₂ × 2^6`.

Для `double`:

- знак: `0`;
- порядок: `6 + 1023 = 1029 = 10000000101₂`;
- мантисса: `1100011011001100110011001100110011001100110011001100`.

**Ответ:**

`0 | 10000000101 | 1100011011001100110011001100110011001100110011001100`

Точная запись невозможна, потому что `0.7` не имеет конечной двоичной записи.

`1.0011e18 = 0.0010011e21`

## Задание 4

```python
x = 99.99
int(x/10+0.001)
```

Получается `9`, хотя ожидается `10`.

Причина в том, что десятичные дроби вроде `99.99` часто нельзя точно записать в двоичной системе. Поэтому вместо `10.0` может получиться число вроде:

`9.999999999999998`.

`int()` просто отбрасывает дробную часть:

`int(9.999...) = 9`.

Если нужно округление, используем:

```python
x = 99.99
print(round(x / 10 + 0.001))
```

Получим `10`.

## Задание 5

```python
x = 1/3
y = 1
for i in range(20):
    print((x+y)-y)
    y *= 10
```

Математически:

`(x + y) - y = x = 1/3`.

Но `double` хранит числа с ограниченной точностью. Когда `y` становится очень большим, маленькое `x = 1/3` при сложении теряется.

Точность `double` примерно:

`2^-52 ≈ 2.22 × 10^-16`.

Потеря становится возможной, когда:

`y × 2^-52 ≈ 1/3`

то есть примерно при:

`y ≈ 1.5 × 10^15`.

Поэтому сначала программа выводит значение около `0.333333`, а при больших `y` результат начинает отличаться и может стать `0`.

## Задание 6

Максимальное конечное значение `double` примерно:

`1.8 × 10^308`.

При этом:

`2^1024 ≈ 1.8 × 10^308` — ещё помещается.

А:

`2^1025 ≈ 3.6 × 10^308` — уже не помещается.

Поэтому минимальное значение:

**`n = 1025`**

и программа выведет `inf`.

Для `long double` диапазон обычно больше. На типичной x86-системе переполнение происходит примерно около `n = 16384`, но это зависит от платформы.

#include <iostream>

int main() {

поэтому условие выполняется и выводится:

## Задание 9

Нужно сравнить:

`p1/q1 + p2/q2`

и

`p3/q3 + p4/q4`.

Чтобы не использовать `double`, сравниваем дроби через крестное умножение.

```cpp
#include <iostream>
using namespace std;

int main() {
    long long p1, q1, p2, q2;
    long long p3, q3, p4, q4;

    cin >> p1 >> q1;
    cin >> p2 >> q2;
    cin >> p3 >> q3;
    cin >> p4 >> q4;

    long long a = p1 * q2 + p2 * q1;
    long long b = q1 * q2;

    long long c = p3 * q4 + p4 * q3;
    long long d = q3 * q4;

    if (a * d > c * b)
        cout << 1;
    else if (a * d < c * b)
        cout << -1;
    else
        cout << 0;

    return 0;
}
```

Если первая сумма больше — выводится `1`, если равна — `0`, если меньше — `-1`.
