$$
123_{10}=1111011_2
$$

**2. Перевод дробной части.**

$$
\begin{aligned}
0.4\cdot2&=0.8 &&\Rightarrow 0\\
0.8\cdot2&=1.6 &&\Rightarrow 1\\
0.6\cdot2&=1.2 &&\Rightarrow 1\\
0.2\cdot2&=0.4 &&\Rightarrow 0
\end{aligned}
$$

Остаток $0.4$ повторяется, поэтому:

$$
0.4_{10}=0.(0110)_2
$$

Следовательно,

$$
123.4_{10}=1111011.0(0110)_2
$$

**3. Нормализация числа.**

Переносим двоичную точку так, чтобы перед ней осталась одна единица:

$$
123.4\approx1.111011011001100\ldots_2\cdot2^6
$$

Тип `double` использует 64 бита: 1 бит для знака, 11 бит для порядка и 52 бита для дробной части мантиссы.

Число положительное, поэтому знак равен 0. Смещённый порядок равен $6+1023=1029$, то есть $10000000101_2$.

Представление с округлённой мантиссой:

```text
0 | 10000000101 | 1110110110011001100110011001100110011001100110011010
```

Двоичная дробь бесконечна, поэтому в `double` её приходится округлять до 52 бит мантиссы. Значение 123.4 нельзя точно представить в двоичной системе, поэтому в памяти хранится ближайшее представимое число.

### Задание 5 **(2)**

*Рассмотрите следующую программу. Объясните результаты ее работы. В частности,
как величина* $y$ *повлияла на ответ?*

```python
x = 1/3
y = 1
for i in range(20):
    print((x+y)-y)
    y *= 10
```

*В отчете требуется привести вычисления для оценки погрешности.*

**Ответ**

Число $x=1/3$ нельзя точно представить конечной двоичной дробью, поэтому в `double` оно хранится приближённо. Кроме того, тип `double` имеет ограниченную точность.

Когда `y` растёт, разница между соседними представимыми числами около `y` тоже увеличивается. Поэтому при сложении `x + y` небольшая добавка `x` может потеряться. После вычитания `y` результат может оказаться равным нулю.

Для чисел порядка $y$ расстояние между соседними значениями примерно равно $y\cdot2^{-52}$. Здесь $2^{-52}\approx2.22\cdot10^{-16}$ — машинная точность `double` около единицы.

Чем больше `y`, тем больше абсолютная погрешность при сложении. Поэтому сначала результат близок к $1/3$, а при больших `y` он может стать неточным или равным нулю.

### Задание 6 **(2)**

*Для какого минимального значения* $n$ *программа на С++ выведет* **inf**? *Объясните
ответ.* *Что произойдет, если тип* **double** *заменить на* **long double**?

```cpp

```

**Ответ**

В обычном формате `double` наибольшие конечные числа имеют порядок примерно $2^{1024}$. Само число $2^{1024}$ уже не представимо как конечное значение типа `double`, поэтому при вычислении степени двойки происходит переполнение.

Минимальное значение:

$$

$$

В этом случае результатом будет бесконечность, обозначаемая `inf`.

При замене `double` на `long double` результат зависит от компилятора и платформы. На распространённых системах x86 с расширенным форматом `long double` максимальный порядок близок к $2^{16384}$, поэтому переполнение степени двойки наступает примерно при $n=16384$. На других платформах `long double` может иметь тот же диапазон, что и `double`.

### Задание 2 **(4)**

*Напишите программу для решения следующей задачи.*

*Даны четыре вещественных числа a, b, c, d, не превосходящие 100 по модулю, записанные не более чем с 10 знаками после точки. Требуется сравнить суммы a+b и c+d и определить, какая из них больше. Возможен случай, что суммы будут равны.*

*От вас требуется обосновать выбор значения* **eps** *при сравнении.*

**Ответ**

При вычислениях с `double` может возникать небольшая ошибка округления. Поэтому суммы сравниваются с учётом допуска `eps`.

```cpp
#include <iostream>
#include <cmath>
using namespace std;

int main() {
    double a, b, c, d;
    cin >> a >> b >> c >> d;

    double s1 = a + b;
    double s2 = c + d;

    const double eps = 1e-12;

    if (fabs(s1 - s2) < eps)
        cout << 0;
    else if (s1 > s2)
        cout << 1;
    else
        cout << -1;

    return 0;
}
```

Если модуль разности сумм меньше `eps`, суммы считаются равными. Иначе программа выводит `1`, если первая сумма больше, и `-1`, если меньше.

Выбрано значение $eps=10^{-12}$, потому что входные числа ограничены по модулю 100 и содержат не более 10 знаков после точки. Ошибки округления при сложении таких чисел в `double` обычно значительно меньше этого порога.

`eps` не является универсальным значением для любых задач: его выбирают с учётом масштаба чисел и требуемой точности.

### Задание 3 **(5)**

*Задано вещественное число в десятичной записи. Напишите программу для нахождения первых 1000 разрядов этого числа в двоичной записи.*

**Ответ**

Чтобы получить двоичные разряды дробной части, нужно многократно умножать её на 2. Целая часть результата становится очередным двоичным разрядом, а оставшаяся дробная часть используется на следующем шаге.

Для точного чтения десятичного числа используем `Fraction`.

```python
from fractions import Fraction

s = input().strip()
x = Fraction(s)

integer = x.numerator // x.denominator
remainder = x - integer

result = bin(integer)[2:] + "."

for i in range(1000):
    remainder *= 2

    if remainder >= 1:
        result += "1"
        remainder -= 1
    else:
        result += "0"

print(result)
```

Программа выводит целую часть в двоичной системе, затем точку и 1000 двоичных разрядов дробной части. Если запись дроби периодическая, цифры будут повторяться. Если дробь заканчивается раньше, оставшиеся разряды будут нулями.

long double acos_e(long double x, long double ep) {

Функция `acos_e(x, ep)` дополнительно учитывает небольшие погрешности вычислений:

Дополнительные проверки позволяют учитывать малые ошибки округления, не скрывая действительно недопустимые аргументы.

### Задание 5 **(5)**

*Заданы координаты точек* $A$, $B$, $C$ *на плоскости. Координаты являются вещественными числами в диапазоне* $[0;10)$ *и содержат не более 6 знаков после точки. Используя формулу векторного произведения, напишите программу для определения расположения* $C$ *относительно вектора* $AB$ *(слева, справа, на прямой).*

*От вас требуется обосновать выбор значения* **eps** *при сравнении.*

**Ответ**

Пусть заданы точки $A(x_A,y_A)$, $B(x_B,y_B)$ и $C(x_C,y_C)$. Вычислим ориентированное векторное произведение:

$$
D=(x_B-x_A)(y_C-y_A)-(y_B-y_A)(x_C-x_A)
$$

- Если $D>0$, точка $C$ находится слева от вектора $AB$.
- Если $D<0$, точка $C$ находится справа от вектора $AB$.
- Если $D=0$, точка находится на прямой, проходящей через $A$ и $B$.

Так как координаты вещественные, при сравнении используем небольшую погрешность `eps`.

```cpp
#include <iostream>
#include <cmath>
using namespace std;

int main() {
    double xa, ya, xb, yb, xc, yc;
    cin >> xa >> ya >> xb >> yb >> xc >> yc;

    double d = (xb - xa) * (yc - ya)
             - (yb - ya) * (xc - xa);

    const double eps = 1e-12;

    if (d > eps)
        cout << "left";
    else if (d < -eps)
        cout << "right";
    else
        cout << "on";

    return 0;
}
```

Здесь `left`, `right` и `on` означают соответственно «слева», «справа» и «на прямой».

**Обоснование `eps`.**

Координаты находятся в диапазоне от 0 до 10 и содержат не более шести знаков после точки. При вычислении разностей и произведений могут появляться небольшие ошибки округления `double`. Порог $10^{-12}$ помогает не считать такие небольшие ошибки ненулевым векторным произведением.
